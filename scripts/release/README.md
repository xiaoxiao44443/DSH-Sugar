# Release companion archives

`package-companions.py` uses Python 3.11+ and its standard library on Windows or
Linux. It reads the **final APK**, not a previous debug build or local staging
directory. Run after the APK has been signed and its package/version/signature
have been verified:

```sh
python scripts/release/package-companions.py \
  --apk dist/DSH-Sugar-0.2.0-arm64-v8a.apk \
  --project-root . --sucrune-root ../Sucrune --version 0.2.0 \
  --output-dir dist --cache-dir .cache/release-companions
```

Outputs:

- `third-party-notices.zip`: upstream notices, included source/build information,
  licenses extracted from this APK, npm lock and dependency audit.
- `debian-corresponding-source.zip`: the complete `.dsc` and source archive sets
  corresponding to the locked Debian binaries.

The caller writes the final `SHA256SUMS.txt` after packaging. The script does not
handle signing keys, create a Release, or upload anything.

## Verification and cache

Every downloaded input has a locked HTTPS URL, byte count and SHA-256. Downloads
retry three times, use a timeout, reject unexpected length/content and write the
cache atomically. Cached files are rehashed before use. GitHub Actions may cache
this directory; cache contents never replace integrity checks.

The Debian index must match its lock digest. Every binary must have a resolved
source and every `.dsc` must match the source name/version and exact set of source
archive hashes. Unresolved or changed sources fail the build. Output archives
use sorted entries, fixed timestamps and fixed modes. They contain no local
machine paths.

## Updating dependencies

The lock is an audited baseline, not an automatic dependency detector. It checks
the files inside the APK's guest/network/Python/time-zone ZIPs, prebuilt native libraries,
pnpm, embedded notices, the DSH npm lock and Android direct dependencies. ZIP
timestamps, compression and ordering do not affect payload fingerprints.
Application UI/Java/Kotlin changes do not require an update. Sugar's declared DSH
JavaScript patches and its own command wrappers are excluded from upstream file
fingerprints; their current source remains in the application repository.
Sucrune's three locally built libraries are checked by required APK entry names
and the clean, pinned source checkout used by CI, rather than by host-dependent
binary hashes. Changed upstream dependency payloads stop packaging.

To inspect a newly built APK without downloading or producing archives:

```sh
python scripts/release/package-companions.py --inspect \
  --apk path/to/final.apk --project-root . --sucrune-root ../Sucrune
```

When it reports changes, first identify the changed upstream components and
verify their versions, source archives, notices and build inputs. Update
`debian-sources.json` when Debian binaries change; update `upstreamInputs` and the
source references in `companions-lock.json` when other dependencies change.
Only after that review, replace the matching `apkDependencies` values and
`debianSourcesSha256` (SHA-256 of canonical UTF-8 JSON generated by `json_bytes`).
Do **not** automatically accept a new fingerprint in CI, or reuse an old source
archive merely because the app version changed.

The initial audit covers Sucrune commit
`f9eb0a1f51c256c151fd63e6d4503c7335c8c11a`, DSH `0.2.2-rc.3`, Node
`24.22.2`, npm `11.19.1` and pnpm `10.28.2`. The Debian lock contains 82 binary
packages mapped to 62 source packages. Full upstream file URLs, sizes and hashes
are in the two JSON files.
