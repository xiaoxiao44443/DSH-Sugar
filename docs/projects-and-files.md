# DSH Sugar 的项目、工作区与文件

Android 工作区实现与设计，2026-11-08。App 的 DSH Host 运行在一个控制环境中。DSH 登记的工作区按需获得自己的 Sucrune 项目环境，项目里的对话复用这个环境。登记默认工作区和打开侧栏「插件」都由 Host 完成。首次使用项目文件、工具或终端时会准备项目环境，界面加载若请求了项目文件也会触发准备。

## 工作区共用一份 DSH

这是有意采用的单用户共享设计：同一台手机上的工作区复用配置、插件和对话资料，便于跨项目协作、维护插件及修复 DSH。项目沙箱隔离各自的工作文件与运行环境，不把每个项目变成互不信任的独立 DSH 账户。

`read-only` 限制的是文件写入，不会隐藏已共享的 `.dsh` 内容，也不会自动关闭独立配置的网络出站能力。因此，它不承诺对其他项目保密共享的凭据和历史记录。允许写入共享配置或宿主插件时，也意味着允许改变所有会话使用的控制环境；这一信任范围见 [Root 设计说明](root-access.md#信任范围)。

所有普通工作区在 `/home/sugar/.dsh` 访问 Host 的同一份用户数据，包括模型配置与凭据、插件、附件和对话记录。读取、修改及删除仍受当前 DSH 会话权限约束。在允许写入的会话里修改共享数据后，其他工作区再次读取即可看到。工作区文件、home 下的其他文件、临时目录及项目进程仍归各自的沙箱所有。侧栏「插件」管理共享的 DSH Web profile，安装、停用和卸载沿用 DSH 的审批流程。

`/opt/dsh` 是 DSH 程序的安装目录，包含程序代码及随版本分发的插件和依赖。两种诊断模式各用临时用户目录。在诊断工作区的 `repair/.dsh/` 下可以检查和修复原用户数据，在 `repair/dsh/` 下可以修复原程序。结束诊断会清理临时对话，已保存至修复目录的更改会保留。

在 A 创建的本地插件先作为普通源码保存在 A。安装时，Sugar 复制整个包目录并核对内容，插件引用的本地文件应打包在该目录内。项目插件的全局源码位于 `~/.dsh/sugar-plugin-sources/<版本摘要>`，由 DSH 创造模式发布的插件放在 `~/.dsh/profiles/web/created-plugins/<编号>`。其他工作区获准后可以直接编辑这些副本。重新安装可向 DSH 插件管理器提供上述全局源码目录的绝对路径，或从原项目重新发布。第三方 Host 插件的普通 Node 文件 API 通过[插件工作区文件视图](plugin-workspace-files.md)访问调用会话的 `/workspace`，图片等二进制产物可直接落入该项目。无关联工作区的文件操作不能读取或创建 `/workspace`。项目终端、内置文件工具、文件面板和子进程同样按项目路由。

下文的产物库、跨项目导入和旧目录退役仍属于后续设计。

## 工作区文件存在哪里

| 创建时选择的目录 | 项目中的 `/workspace` | 在手机上查看 |
| --- | --- | --- |
| DSH 内部文件夹 | Sucrune 项目的私有目录 | 系统「文件 → DSH Sugar → 项目名」 |
| 手机本地文件夹 | 用户通过 Android 系统选择器授权的原目录 | 该目录在手机存储或 SD 卡上的原位置 |

内部工作区首次启用时，Sugar 把控制环境所选目录的内容导入项目环境，之后读写项目自己的文件。比如项目登记在控制环境的 `/workspace/aaa`，会话里的 `/workspace/index.html` 位于项目根，`/workspace/aaa/index.html` 位于根下的 `aaa` 子目录。子智能体继承父会话的项目身份，工作目录沿用项目内的路径。

每个项目只选一种来源。同一项目内的对话、Shell、文件面板与产物卡读取同一份工作文件。手机下载目录里的导出文件是点「下载」时保存的副本。

Sugar 通过系统文档提供方列举和定位手机本地目录，通过操作系统提供的文件描述符读写文件。手机目录的能力取决于提供方与 Android 存储权限。链接、设备节点以及部分原子替换等 POSIX 操作可能返回错误。手机目录改名、移走或授权被撤销后，可以从系统选择器重新选择。网盘、自定义虚拟文档库不能作为这项本地挂载的来源。

升级后停止旧的文件夹同步。旧沙箱里的文件继续属于原项目，原手机目录里的文件留在原位。需要直接使用原手机目录时，在工作区选择器里选它作为一个独立的手机工作区。

## DSH 和 Sucrune 如何配合

项目对话里的 Bash 默认使用 `workspace-write`。DSH 用 `landlock-run` 探测 Landlock 并启动命令。Sugar 从固定版本 `@deepseek-ai/node-addon-system` 的 C 源码构建 ARM64 启动器，控制环境和项目环境共用 APK 中的同一份可信 ELF。项目工作进程首次调用该启动器时探测并记录支持级别。确认旧 ABI 仅能执行部分限制后，后续命令的标准错误不再重复附带这条提示。启动器设置规则失败和命令自身的错误仍照常返回。每个项目复用一个工作进程，每次命令的文件访问权限由启动器和 Sucrune 确定。可写模式允许写当前项目的 `/workspace` 和 `/tmp`，只读模式下普通文件只可读。共享 `.dsh` 采用独立挂载，普通工作区写权限仍限定在原有范围。额外可写目录及缩小到某个子目录的写入授权会明确拒绝。会话、Shell、文件工具和交付卡共用项目里的路径。例如，登记为 `/workspace/aaa` 的项目，在对话里用 `index.html` 或 `/workspace/index.html` 交付根目录中的网页。

1. 宿主保存稳定映射 `sessionId → workspaceId → projectId → envId`。工作区根路径另存。新建、重命名、恢复与删除按 ID 操作。第一版一个项目只暴露一个工作区根；子目录可以作为命令的当前目录。
2. 控制环境运行完整的 DSH。项目环境装载所需的 Linux 工具，并单独保存项目依赖。原有项目若在自己的 `/home/sugar/.dsh` 中存过文件，升级后会在同级的 `.dsh-before-sharing` 中保留它们，重名时追加数字。项目现在通过 `/home/sugar/.dsh` 访问控制环境的用户数据。
3. 上游 DSH 的工作区注册会在本进程中对目录做 `realpath/stat`，恢复会话时也使用目录识别工作区。适配器要给控制端可区分的工作区身份，并在执行时翻译为项目内的 `/workspace`。文件面板、Agent 读写与补丁、终端、后台进程、预览和产物读取均须按发起会话绑定的项目分发。字符串前缀比较无法验证带符号链接的路径。项目进程不应获得其他环境的宿主路径、控制端凭据、系统文件授权或跨项目管理能力。侧边终端还要处理窗口大小、前台信号和作业控制。可以先在各项目环境中按需运行薄的 PTY 助手，复用 node-pty；这个助手只负责终端。
4. 上游 `present` 目前在会话事件 `deliverables/presented` 中记录文件路径。建议在交付时从绑定环境中打开普通文件并流式复制到宿主产物库，成功后提交 `artifactId`、项目、文件名、大小和内容摘要。记录关联具体内容版本。再次构建、改名和删除工作文件都不会改变已交付版本。由用户在目标项目选定产物导入；项目工具只可访问明确授予的产物。
5. Sucrune 已有按环境读写文件、执行命令和删除项目的接口。当前小文件读写上限为 1 MiB，流式导入单文件至多 256 MiB；导出大型 APK、视频和压缩包需要补对称的流式读取、取消及失败清理。项目之间的端口仍可能冲突，验收文件隔离和进程归属时需单独检查本机服务访问。

## 从项目终端查看进程和网络

- `top -b -n 1` 采样当前工作区 `/proc` 中可见的进程，列出 PID、状态、CPU 和常驻内存。CPU 按单个核心的占用率计算，RSS 以 KiB 显示。其他工作区的进程不列入统计。
- `nslookup example.com` 使用项目 `/etc/resolv.conf` 中的 `127.0.0.53`。Sucrune 将查询交给 Android 当前网络的解析器。显式指定其他 DNS 服务器时，能否访问由网络和沙箱策略决定。
- `getent hosts localhost` 走项目里应用使用的 libc 名称解析，可以和直接查询 DNS 的 `nslookup` 对照。`hostname` 输出客体的主机名，`getconf PAGESIZE` 输出客体程序使用的内存页大小。
- `ping -c 3 <地址>` 使用无特权 ICMP Echo 数据报，支持 `-4` 和 `-6`。收到回包才报告往返时间，目标或网络丢弃 ICMP 时会超时。
- `ss -lnt` 或 `netstat -lnt` 列出本工作区的 TCP 监听端口，`ss -lntu` 或 `netstat -lntu` 同时列出 UDP 端口。支持 IPv4 和 IPv6。命令从 `/proc/net/{tcp,tcp6,udp,udp6}` 获取打开时的快照。进程关闭最后一个套接字引用后，再查询就能看到变化。
- 项目共享手机网络和端口。即使服务属于另一个项目，只要地址可达且策略允许，`nc -z -w 2 127.0.0.1 8080` 也能测试 TCP 连接。退出码 0 表示连接已建立，`-v` 可显示诊断。


## 系统文件和产物菜单

内置 DSH 插件 `dsh-sugar-file-actions` 通过上下文菜单注册「下载」「使用默认应用打开」「在文件夹显示」。插件用发起会话的文件权限分段读取产物，Android 把下载发布到公共 Download 目录。外部应用收到按文件授权的只读内容 URI。通过「在文件夹显示」可打开文件的父目录；目录菜单直接打开该目录，项目菜单和文件页的工作区根菜单打开工作区根。

Android 的 DocumentsProvider 在系统「文件」里列出活动和已移除的内部工作区文件夹，支持浏览、打开，以及删除文件和非空目录。删除会作用在真实的项目内容上。手机工作区由手机存储原来的提供方管理。

工作区插件 `dsh-sugar-workspace` 在目录选择器中提供选择手机文件夹和删除普通空目录的入口。移除工作区后，DSH 保留会话历史。再次添加原内部目录时恢复其工作文件，并关联仍存在、属于该项目的会话。要删除已移除的目录，可在系统「文件」中清空其内容，再从 DSH 目录选择器删除空文件夹。

工作区列表支持按大小、创建时间或修改时间排序；其中创建时间来自 DSH 的工作区注册记录。工作区文件列表按大小、文件名或修改时间排序；文件名默认升序，名称中的数字按自然顺序排列（如 file2 在 file10 前）。两种列表均可切换升序和降序，按时间排序时日期缺失的项目始终排在最后。

## 生命周期和迁移

- 停止项目执行可释放工作进程，工作区和依赖保留。
- 从 DSH 移除手机工作区会停止沙箱并释放目录授权，手机原目录和公共下载副本保留。移除内部工作区时，Sugar 把项目的工作目录和托管硬链接文件留在应用私有存储，回收沙箱。在系统「文件 → DSH Sugar」中可继续访问该目录。
- 升级时，项目 home 内旧的非空 `.dsh` 会在首次启动该项目时改名为 `.dsh-before-sharing`。同名备份已存在时使用带编号的名字。原有文件可在该项目里找回。
- 卸载或清除应用数据会移除内部项目。希望单独保留的文件可以通过产物菜单下载到手机。[Android 应用专属存储](https://developer.android.com/training/data-storage/app-specific)

实现对照可见 [DSH Sugar 的镜像和数据布局](../README.md)、[Sucrune 项目生命周期](../../Sucrune/docs/project-lifecycle.md) 和 [Sucrune 文件及执行 API](../../Sucrune/docs/api.md)。
